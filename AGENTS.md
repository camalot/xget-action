# AGENTS.md

Guidance for AI coding agents working on **xget-action**, a TypeScript GitHub Action
(Node 24) that installs the [xget](https://github.com/camalot/xget) CLI, caches the
binary, and can optionally run it to install a package.

## Quick commands

| Task | Command |
| --- | --- |
| Install deps | `npm ci` |
| Tests (Jest + coverage) | `npm test` |
| Lint | `npm run lint` / `npm run lint:fix` |
| Format | `npm run format` / `npm run format-check` |
| Build bundled `dist/` | `npm run build` |
| Everything before committing | `npm run pre-checkin` (format, lint:fix, build, test) |

- The Node version is pinned in `.nvmrc`. `package.json` requires `>=24`.
- The package is ESM (`"type": "module"`). Jest runs with `--experimental-vm-modules` and
  `ts-jest` ESM preset (`jest.config.js`, `tsconfig.test.json`).

## `dist/` must be committed

`action.yml` runs the bundled files, not `src/`:

- `main: dist/setup/index.js` (from `src/setup-xget.ts`)
- `post: dist/cache-save/index.js` (from `src/cache-save.ts`, runs only on success)

After **any** change under `src/`, run `npm run build` and commit the updated `dist/`.
CI fails if `git status --porcelain dist/` is not clean after a rebuild. Never edit
`dist/` by hand.

## Layout

```text
action.yml            Action metadata: inputs, outputs, node24 runtime, main/post entry points
src/setup-xget.ts     Main entry: resolve version, restore/download/cache xget, add to PATH, optionally run xget
src/cache-save.ts     Post step: save the downloaded binary to the Actions cache
src/cache.ts          Thin wrappers around @actions/cache
src/context.ts        Reads action inputs into ActionInputs
src/xget-cli.ts       buildXgetArgs(): maps inputs to xget CLI flags
src/version.ts        Resolves "latest"/version input to a release tag via the GitHub API
src/download.ts       Downloads and extracts the xget release archive for the platform
src/platform.ts       Maps runner OS/arch to release asset names and binary names
src/state-helper.ts   Passes state (cache hit/key/path) from main to post step
src/constants.ts      Shared constants (TOOL_NAME, repo, etc.)
__tests__/*.test.ts   Jest unit tests (one file per module)
.github/linters/      Lint configs (ESLint flat config, super-linter env, yamllint, markdownlint, codespell, zizmor, ...)
```

## Adding or changing an input

Update all of these together:

1. `action.yml`: add the input with a description and default.
2. `src/context.ts`: add it to `ActionInputs` and `getInputs()`. Use `getBooleanInput` or
    `getMultilineInput` where appropriate.
3. `src/xget-cli.ts`: map it to an xget flag in `buildXgetArgs()`, if it maps to one.
4. `__tests__/`: add or adjust tests (e.g. `xget-cli.test.ts`).
5. `README.md`: update the inputs table and examples.
6. `npm run build` and commit `dist/`.

`buildXgetArgs` rules to keep:

- If the `args` input is non-empty, **only** `[package, ...args]` is passed. No other flags
  are added.
- Otherwise it always appends `--non-interactive` and `--untracked`, and adds `--verify`
  unless `skip-verify` is true. `--to` defaults to `/usr/local/bin`.
- Flag names must match the xget CLI (`xget --help`). Check the xget repo before adding
  or renaming a flag.

## Conventions

- Use `@actions/*` libraries (`core`, `exec`, `tool-cache`, `cache`, `http-client`) instead
  of shelling out or using raw `fetch`, so behavior stays consistent on all runners.
- Report failures with `core.setFailed(...)` at the entry point. Don't call `process.exit`.
- Never log the `token` input. It is passed to xget only via the `GITHUB_TOKEN` env var.
- Keep the action cross-platform (Linux, macOS, Windows runners; x64 and arm64). Use
  `path.join` and handle `.exe` binary names through `platform.ts`.
- Tests must not hit the network; mock `@actions/*` modules and HTTP calls with Jest.
- Formatting follows `.prettierrc.json`. Linting follows `.github/linters/eslint.config.js`.
  CI also runs super-linter (`camalot/actions/smells/lint`), which checks YAML, Markdown,
  spelling, secrets (gitleaks), and workflow security (zizmor).
- Workflows use `permissions: {}` at the top level, least-privilege per job, and
  `persist-credentials: false` on checkout. Keep that pattern.

## Commits and releases

- Use [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`,
  `chore(deps):`, `docs:`, ...). `CHANGELOG.md` is generated by git-cliff (`cliff.toml`).
- Releases are cut manually via `.github/workflows/release.yml` (`workflow_dispatch`). It
  computes the next version, rebuilds and commits `dist/`, publishes `vX.Y.Z` plus the
  moving `vX` and `vX.Y` tags, and attaches a `dist/` tarball with an SBOM and
  provenance attestation. Consumers reference `camalot/xget-action@v1`, so avoid breaking
  input changes within a major version.

## Related repositories

- **xget** (`camalot/xget`): the CLI this action installs and runs. Release asset naming
  there determines what `platform.ts` and `download.ts` expect.
- **actions** (`camalot/actions`): shared lint, coverage, and version actions used by this
  repo's workflows.
